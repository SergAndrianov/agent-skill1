# ПлатиДом — автоплатёж с лимитом суммы

Диаграмма C4 уровня 2 показывает, как клиент управляет правилом автоплатежа, как ПлатиДом проверяет условия списания и как отслеживает исход операции. Представление `AutoPaymentLimit` находится в [workspace.dsl](workspace.dsl). Статус модели — черновик. Актуальность начисления, проверку источника и средств, а также контракт сверки статуса ещё предстоит подтвердить.

## Как обрабатывается автоплатёж

1. **Настройка.** API читает привязку по идентификатору и проверяет её владельца. При включении или изменении требует доступный клиенту источник оплаты, положительный числовой лимит в рублях и подтверждённое согласие. При ошибке возвращает конкретную причину и сохраняет прежнее состояние. Ограничение уникальности в БД позволяет сохранить одну текущую конфигурацию на привязку. Повторное подтверждение обновляет эту конфигурацию. Отключение меняет состояние на «отключено».
2. **Проверка перед отправкой.** При запуске API сопоставляет начисление с собственной привязкой и проверяет активность правила, актуальность и неоплаченность начисления, положительную сумму и достаточность средств. Лимит проверяется по полной сумме одного начисления и включает равенство. При превышении лимита, нехватке средств, отключённом правиле или уже оплаченном начислении API сохраняет причину пропуска без платёжного запроса. Изменение и отключение правила учитываются до передачи платежа. Уже отправленная попытка продолжает отслеживаться.
3. **Резервирование попытки.** API до отправки атомарно резервирует в БД уникальную запись по ключу начисления и закрепляет за ней неизменяемый ключ исходной попытки. Область уникальности ID начисления и срок защиты остаются открытыми в Q-05. Устойчивый признак права на отправку должен давать его только одному обработчику. Обработка дубля использует уже сохранённый итог или проверяет исходную попытку, если запрос мог уйти в процессинг. Точка передачи должна быть согласована с изменением или отключением правила.
4. **Платёжный запрос.** API передаёт ID начисления и полную сумму с валютой, выбранный источник списания и сохранённый ключ исходной попытки. ID начисления определяет оплачиваемое обязательство, источник определяет, откуда списать средства, ключ попытки связывает платёжный запрос со сверкой результата. Способ распознавания повтора на стороне процессинга нужно подтвердить по A-09.
5. **Подтверждение или сверка.** Подтверждение процессинга переводит попытку в «успешно» с суммой и внешним ID операции. Явный отказ переводит её в «отклонено» с причиной. При тайм-ауте или потере ответа API сохраняет «результат уточняется». Для сверки используется ключ попытки, сохранённый до отправки и доступный до получения внешнего ID. Запрос сверки и его принадлежность процессингу зависят от внешнего контракта. Новый платёж при неизвестном исходе не отправляется. Результат и причина пропуска выдаются в приложение по проверенному владельцу.
