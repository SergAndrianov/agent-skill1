## Самопроверка

| Правило | Что проверено |
| --- | --- |
| Входы сценария | Клиент выбирает собственную сохранённую привязку. Управление правилом и просмотр результата доступны через приложение. |
| Запись и чтение | API читает историю отдельной связью. Настройка, изменение и отключение имеют отдельную команду. У процессинга команда оплаты и чтение статуса различимы. |
| Источники и контракт | Технологии связаны с A-14, отдельный обработчик — с A-17. Условные проверки инструмента и средств, сверка по ключу и открытый контракт срока приёма отмечены на связях. |
| Объект операции и сверка | Команда передаёт ID начисления, полную сумму, валюту, источник и ключ. До внешнего ID статус ищется по заранее сохранённому ключу при подтверждённом контракте. Потеря ответа не разрешает новую отправку. |
| Параллельное исполнение | Фоновый обработчик планирует работу и захватывает задания с маркером владения. Одноразовый допуск и уникальная попытка сохраняются в БД. Проверены немедленное отключение без открытого допуска и отключение с допуском после его предельного срока с поправкой на часы. Пропавший обработчик не блокирует переход. После потери ответа остаётся сверка старой операции. |
| Нагрузка | Расчёт A-16 даёт 8,33 кандидата/с, до 41,67 фонового внешнего вызова/с и до 75 транзакций записи/с по указанной модели. Учтены совместный пик и удвоение. |
| Критерии | Сверены 11 критериев. Проверены границы лимита, отсутствие отправки при пропуске, параллельный повтор, потеря ответа до внешнего ID, отключение и доступ только к своим данным. |
